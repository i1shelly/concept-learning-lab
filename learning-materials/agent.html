Agent（智能体）

能自主规划、调用工具、循环行动，直到完成任务的 AI 系统

2核心问题

  • 同样是"用 AI"，Agent 和聊天机器人到底差在哪？
  • Agent 靠什么决定"下一步做什么"？
  • 什么时候不该用 Agent？

3我的解释

在我看来，Agent 就是"长出手脚的大模型"。普通的 AI 对话像咨询台：你问一句、它答一句，事情还得自己去做。Agent 不同——你给它一个目标，它自己拆任务、挑工具、动手执行、看结果，发现不对就调整，循环往复直到把事情办完。

做这份作业时我近距离观察了一次：从"帮我完成作业"一句话开始，AI 自己检查了 git 环境、发现身份没配置就先配置、克隆仓库、写文件、准备提交推送——每一步都是"想一步、做一步、看结果、再想"。这个循环，就是 Agent 的呼吸方式。

4核心机制与组成

四个核心部件

部件角色说明
大脑LLM 负责推理与决策理解目标、规划步骤、决定下一步调用什么（ReAct 式的"思考→行动→观察"）
手脚工具（Tools）搜索、代码执行、文件读写、API 调用等，是 Agent 真正"做事"的途径
循环感知 → 思考 → 行动 → 观察每一轮行动的结果成为下一轮决策的输入，直到任务完成或触发停止条件
工作记忆上下文（Context）累积的指令与观察构成它决策的全部依据——见本仓库 llm-context.html

经典架构（Lilian Weng，2023）

Agent = LLM（大脑）+ 规划（子目标分解、反思与改进）+ 记忆（短期=上下文，长期=外部存储）+ 工具使用（调用外部 API）。这是被引用最多的 Agent 架构综述。

Workflow vs Agent（Anthropic 的划分）

维度Workflow（工作流）Agent（智能体）
控制流由预先写好的代码路径编排由 LLM 动态决定自己的流程和工具使用
适合的任务步骤固定、定义清晰开放性、无法预先预测步骤数
可预测性高较低
成本 / 延迟较低较高（多轮模型调用）

Anthropic 后来把定义收敛成一句话："Agents are LLMs autonomously using tools in a loop"（Agent 就是在循环中自主使用工具的大模型）。

5应用场景：本仓库的诞生过程

完成本次作业就是一个真实的 Agent 任务。目标"建仓库 + 写 Skill + 生成资料 + 推送"无法靠一次问答完成，实际执行链是：

  1. 检查 git 版本 → 发现 user.name/email 未配置
  2. 根据观察调整：先配置身份，再克隆空仓库
  3. 创建 Skill → 检索并验证来源 → 生成三份资料
  4. 提交、推送 → 若遇认证问题，换方式处理

每一步都根据上一步的观察结果决定。如果这是固定脚本（Workflow），任何一环出现意外（比如仓库非空）流程就会中断；Agent 的价值恰在于能对意外做出反应。

6概念辨析与边界

容易混淆的对象区别在哪
会聊天的 AI对话产出的是"话"，Agent 产出的是"事"。判断标准：有没有工具调用与自主循环
Workflow分界线是"谁指挥流程"：人写死的代码 vs LLM 自己决定
RPA 脚本RPA 按固定步骤执行、遇变即停；Agent 动态决策、遇错可调

使用边界（什么时候不适用）

  • 任务需要能被观察和验证——没有反馈，循环就失去方向
  • 延迟和成本高于单次对话，简单任务"直接问"更划算（Anthropic 的建议：从最简单的方案开始）
  • 错误会随步数累积，关键节点需要人把关（本次作业中 push 前由本人确认，就是一道人工关卡）

1.（简答）用一句话说出 Agent 与普通 LLM 对话最本质的区别。

参考答案

Agent 由 LLM 在循环中自主决定流程并调用工具去完成任务；普通对话只是生成文本，不行动。

B。Workflow 的控制流预写在代码里；Agent 由 LLM 动态决定。
