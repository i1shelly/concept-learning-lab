大模型的上下文（Context）

模型每次回答时能"看到"的全部信息——既是工作记忆，也是稀缺资源

学习主题：大模型的上下文 ｜ 生成日期：2026-09-08 ｜ 初稿由 AI 按 Skill 流程生成，经作者核查（记录见仓库 README）

1学习目标

  1. 能解释上下文窗口是什么、以什么计量、目前大致什么量级
  2. 能列出一次对话中上下文的组成部分，并说明每部分从哪来
  3. 能描述上下文影响 AI 表现的三种方式（截断、注意力稀释、位置偏差），并说出至少两种管理策略

2核心问题

  • 为什么新开一个对话，AI 就"忘了"之前聊过的所有内容？
  • 把 50 页资料全部塞给 AI，它为什么反而答得更差？
  • 大家说的"上下文工程"到底在工程什么？

3我的解释

我把上下文理解为"大模型答题时桌面上摊开的所有材料"。每次我发一条消息，模型看到的从来不只是这一句话，而是整张桌子：系统设定、之前的对话、我上传的文档、工具返回的结果——全部同时摊在它眼前。它答得好不好，很大程度取决于桌上的材料齐不齐、摆放有没有条理。

这张桌子有两个特点让我印象很深：一是大小有限（上下文窗口），塞太满反而互相干扰，重要的东西被淹没；二是每次对话结束桌子就会被清空——它并不真的"记得"我。所谓"记得"，只是这次会话里材料还在桌上而已。

4核心机制与组成

怎么计量：token

上下文以 token 计量：英文约 4 个字符 ≈ 1 个 token；中文一个汉字通常折合 1~2 个 token。主流模型的窗口已从早期的 4K~32K 扩展到 128K~1M 量级——听起来很大，但一次真实任务（长对话 + 检索资料 + 工具结果）会很快把它填满。

上下文里都有什么

组成部分来源
系统提示（System Prompt）产品或 Skill 注入的角色设定、规则、工具说明
对话历史本次会话中你来我往的所有消息
附件与检索内容上传的文档、RAG 检索到的片段、Skill 正文
工具定义与工具结果Agent 调用工具后回传的观察结果

Anthropic 官方课程的表述：上下文是"每一次模型调用的输入"，包括系统提示、消息历史、工具定义与结果、附件与 Skill、思考块——输入按 token 计费，输出同样计费；窗口一旦填满，请求就失败。

注意力：一切"同时被看"，但权重不同

Transformer 的注意力机制对上下文中所有 token 同时分配权重，由相关性和位置决定强弱——不是"读到哪算哪"。这带来两个重要现象：

  • Lost in the middle：斯坦福团队的实验表明，关键信息位于上下文开头或结尾时模型表现最好，位于中部时显著变差（U 形曲线）；极端情况下，关键文档放在中间的表现甚至不如不给文档。专为长上下文设计的模型同样存在此现象。
  • 上下文腐烂（context rot）：随着进入上下文的 token 增多，模型准确回忆信息的能力单调下降——更多材料反而互相稀释注意力。

三种"知识"的对比

训练权重上下文外部存储
存的是什么预训练学到的知识本次任务的指令与材料文件、向量库、记忆工具
生命周期固化，难以即时更新本次调用生效，会话结束即消失持久保存
进入方式训练时写入随请求直接携带按需检索进上下文

上下文工程：把上下文当稀缺资源经营

Anthropic 把"上下文工程"定义为在推理全程持续维护"最小的高信号 token 集合"。常用策略：

  • 压缩（compaction）：把冗长历史总结成精炼摘要，腾出空间
  • 结构化笔记：把关键状态写成结构化文件，按需回读
  • 子 Agent 隔离：让子任务在独立上下文中完成，只把结论带回主上下文
  • 按需检索（just-in-time）：平时只保存轻量索引（文件路径、链接），用到时再加载

5应用场景：生成这份资料的过程本身

写这份学习资料时，AI 的"桌面"上需要同时放着：作业要求、SKILL.md 的流程、多篇检索结果。如果把来源全文（数万字）全部摊上桌，既挤占空间又稀释注意力——所以本仓库的 Skill 在设计时就规定"验证链接、提炼要点、来源只留清单"，这正是上下文工程里"最小高信号集合"的思路。

另一个我亲历的现象：长对话进行到后期，AI 开始忘记早期约定、重复确认已经说过的事——那不是模型"坏了"，而是桌面被历史堆满，早期指令被挤到了注意力边缘。对策同样是上下文工程：总结压缩旧对话、把重要状态写进外部文件按需读取。

6概念辨析与边界

容易混淆的说法澄清
"窗口大 = 记忆好"窗口是"单次能看多少"，不是"跨会话记住多少"。新会话 = 空桌面，之前的一切不会自动出现
上下文 = 训练知识一个临时（本次调用），一个固化（权重里）。模型会背唐诗靠训练；记得我刚说的名字靠上下文
塞满 = 更好上下文越长，回忆准确率越低（context rot），中部信息还容易被忽略。有效信息密度比长度重要
RAG / 记忆工具 = 上下文它们是"往桌上递材料"的手段；递进来的部分才成为上下文

使用边界

  • token 是计费单位：上下文越长，成本越高、延迟越大——"够用的最小集合"优于"全部塞进去"
  • 窗口有硬上限：填满即失败，长任务必须主动管理（压缩、外置、隔离）
  • 位置敏感：关键指令和关键材料应放在上下文的开头或结尾，别埋在中间

7自测

1.（简答）为什么新开对话后 AI 不记得之前的内容？

参考答案

模型的"记忆"只存在于上下文中，而每次调用相互独立；新会话的上下文为空，训练权重里也没有这段对话。

2.（名词解释）"Lost in the middle" 指什么现象？

参考答案

关键信息位于长上下文中部时，模型表现显著差于位于开头/结尾（U 形曲线）；该现象在专为长上下文设计的模型上同样存在。

3.（选择）以下哪项不属于上下文的组成部分？　A. 系统提示　B. 对话历史　C. 模型的训练数据　D. 工具返回结果

参考答案

C。训练数据在预训练时固化进权重，不随每次请求进入上下文。

4.（判断）把整本教科书贴进对话，AI 的回答一定更准确。

参考答案

错。超长上下文带来注意力稀释与中部信息丢失，且成本高；正确做法是检索关键部分按需提供。
